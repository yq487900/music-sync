# 下载一致性校验

把「下载到的音频文件」与「网易云对应曲目的实际播放版本」逐项比对，
在**下载完成之后、打标签与归档之前**做一道强制关口。任一比对项不通过，
整首歌判不通过：文件删除、不落下载目录、不自动归档、不上传云盘。

实现：`app/verify.py`（核心）+ `app/sync/netease.py`（流程接入）
独立测试：`tests/verify_check.py`（单文件 / 批量复核 / 离线自测）、`tests/verify_calibrate.py`（阈值标定）

---

## 一、为什么要有这一关

下载链路的现状：

1. 网易云官方直链拿不到（下架、无版权、只剩试听）时，会走第三方音源（洛雪兼容脚本）。
2. 第三方音源给的东西**不保证是对的**：可能是翻唱、Live 版、纯伴奏、钢琴版，
   甚至干脆是另一首歌（实测过给回 JSON 中转页、40 秒试听片段的情况）。
3. 原来只在**第三方音源**下载时做了两道粗检：`sniff_ext`（是不是音频）+
   `looks_like_preview`（时长是不是明显偏短）。这两道只能挡「不是文件」和「太短」，
   挡不住「是音频、时长也对、但不是这首歌 / 不是这个版本」。

本功能补的就是这一段：**用网易云自己播放的那份音频当基准，验货**。

## 二、在流程里的位置

```
歌单/勾选
   ↓
resolve_stream ── 网易云官方优先，拿不到走第三方
   ↓
download ── 落 /data/tmp/xxx.part，边下边算 md5
   ↓
verify(md5/size) + sniff_ext + looks_like_preview
   ↓
改后缀 → /data/tmp/xxx.flac
   ↓
┌──────────────────────────────────────────┐
│  ★ 一致性校验（本功能）                    │   ← 必须在打标签之前
│  时长 / 演唱者 / 专辑 / 音乐 bgm / 歌手声纹  │      （演唱者、专辑比的是
└──────────────────────────────────────────┘       文件自带的原始标签）
   │ 通过                          │ 不通过
   ↓                               ↓
tag_file（写标签/封面/歌词）        删除文件（或留 /data/verify_failed/）
   ↓                               ↓
move_into /music/download/...      status=failed + verify_state=failed
   ↓                               fail_count+1（走正常退避）
auto_archive → /music/musics       不归档、不上传云盘
   ↓
auto_upload → 云盘（如开启）
```

**为什么必须在 `tag_file` 之前**：演唱者和专辑要比对的是**音源方自己打的标签**。
如果先执行 `tag_file`，文件里的歌手/专辑就变成我们刚从网易云写进去的值了，
再拿它去和网易云比，等于自己和自己比，永远通过——毫无意义。

## 三、输入

| 输入 | 说明 |
|---|---|
| `path` | 下载完成、**尚未打标签**的音频文件（`/data/tmp/<名>.<ext>`） |
| `ref`（基准元数据） | `sid` 曲目 id、`title`、`duration`（秒，来自 `/song/detail` 的 `dt/1000`）、`artists`（`ar[].name` 列表）、`album`（`al.name`） |
| `ncm` | `app.ncm.Ncm` 客户端；用于取**官方播放直链**（`/song/url/v1`）作为音频基准 |
| `cfg` | 整份配置（读 `cfg["verify"]`），或直接传 verify 子字典 |
| `source_is_official` | 本次下载是否来自网易云官方直链（配合 `only_third_party` 跳过） |

基准音频的取法（`fetch_reference_audio`）：

- 依次尝试 `standard` → `higher` → `exhigh` 档，取第一个**非试听**直链。
- **只拿 URL，不下载整首**：交给 ffmpeg 用 input seek（`-ss` / `-t`）按需拉约 40 秒，
  实测 4~5 秒、几百 KB。
- 踩过的坑：这个账号拿到的 `standard` 档其实也是 FLAC（26MB、br≈950k）。
  自己用 Range 从中间截 900KB 再解码，ffmpeg 只能解出 7 秒就报
  `invalid residual`（FLAC 帧边界丢了）；**URL seek 能正常解出完整 40 秒**。

## 四、判定逻辑

五项，每项三种状态：`pass` / `fail` / `skip`。

| 项 | 本地值 | 网易云基准 | 判定 |
|---|---|---|---|
| **时长** `duration` | `tinytag` 读时长（失败退 `ffprobe`） | `dt/1000` | `|差| ≤ duration_tolerance`（默认 **2.0s**） |
| **演唱者** `artist` | 文件内嵌 `artist`（`albumartist` 兜底） | `ar[].name` 列表 | 归一化后**至少命中一个**歌手：完全相等 / 互相包含（长度≥2）/ 相似度 ≥0.75 |
| **所属专辑** `album` | 文件内嵌 `album` | `al.name` | 归一化 + 去 `(Deluxe/Remaster/…版)` 后缀后，相似度 ≥ `album_threshold`（**0.82**） |
| **音乐 bgm** `bgm` | 本地音频 40s 片段 | 官方播放流同一时间点 40s | 对数梅尔谱（0.5s 网格 × 26 带）在 ±4s 内滑动对齐后的**平均逐帧相关** ≥ `bgm_threshold`（**0.80**） |
| **歌手声纹** `voiceprint` | 同上 | 同上 | 对齐后 **MFCC 帧级余弦相似度中位数** ≥ `voiceprint_threshold`（**0.62**）**且**基频中位数相对差 ≤ `pitch_tolerance`（**6%**） |

整体判定：

- 有任一 `fail` → **failed**
- 否则 → **passed**（`skip` 不阻止通过，但会在报告里写明原因）
- 全部项都取不到（比如文件不存在、开关关了）→ **skipped**

`skip` 的常见情形：文件没有内嵌歌手/专辑标签（第三方音源没打）、
网易云没有该曲的完整播放流（已下架/无版权/仅试听）、有效人声帧太少（纯音乐）、
环境缺 ffmpeg/numpy。

### 时间轴怎么对齐

两侧都从**本地时长的 35% 处**往前 4 秒开始，各取约 48 秒，
再用梅尔谱互相关在 ±4 秒内找最优 lag（相关接近时优先取 |lag| 小的，避免循环段落选到伪峰）。
同一首歌两侧天然对齐、lag≈0；换版本（Live/翻唱）会整体错位，相关直接掉下去。

### 阈值是实测标定的，不是拍的

2026-10-26 用曲库里真实曲目（林俊杰《曹操》《西界》等 6 首 + 《不为谁而作的歌》Live 版）
做正负样本标定，`tests/verify_calibrate.py` 可复现：

| 场景 | bgm 相关 | 声纹相似度 |
|---|---|---|
| 同一首歌（6 首正样本） | 0.944 ~ 1.000 | 0.728 ~ 1.000 |
| 不同歌（4 个负样本） | 0.430 ~ 0.572 | -0.005 ~ 0.282 |
| Live 版 vs 录音室 | 0.569 | 0.497 |
| 原曲 vs 伴奏/钢琴版 | 0.395 ~ 0.863 | 0.206 ~ 0.817 |

负样本里最难的是「云不死之身-伴奏」：编曲一样，bgm 冲到 **0.863**（超过 0.80 阈值），
但声纹只有 0.577、音高差 36% → **靠声纹项抓住**。这说明两项不是冗余：
**bgm 看编曲/伴奏，声纹看人声**，互补。

标定结果：**6 首正样本 0 误杀，4 个负样本 0 漏放**。

## 五、失败时怎么处理

| 动作 | 说明 |
|---|---|
| 文件 | 默认**直接删除**；`keep_failed=true` 时移到 `/data/verify_failed/<sid>_<歌名>.<ext>` 供人工复查 |
| 函数返回 | `{"ok": False, "verify_failed": True, "verify_report": {...}, "reason": "一致性校验不通过：…"}` |
| 数据库 | `status=failed`、`verify_state=failed`、`verify_report=<完整明细>`、`last_error=<摘要>`、`fail_count+1` |
| 后续流程 | **不写标签、不进 `/music/download`、不自动归档到曲库、不上传云盘** |
| 重试 | 走正常失败退避（`fail_backoff` / `backoff_hours`）。**不会自动换音源重试**——本次范围内不通过就是失败，要换源需要用户在曲目行手动改音源偏好 |
| 积分/计数 | 不打 `[临时故障]` 标记（不是沙箱抖动，是这首歌确实没下对） |

## 六、结果反馈形式

1. **队列任务**
   - 通过：任务「来源」后面追加 `· 一致性校验通过（5/5 项）`
   - 失败：`task.fail()` 的消息即失败原因，如
     `一致性校验不通过：音乐 bgm不一致（音频内容与官方版本不符（谱图相关 0.57 < 0.80））`
2. **下载页**：失败曲目的 `last_error` 显示上面那句摘要（原有 UI 就会显示）。
3. **数据库** `tracks` 表新增三列：
   ```
   verify_state   '' / passed / failed / skipped
   verify_report  JSON：逐项明细（state / local / ref / score / detail）+ 基准信息
   verify_at      校验时间
   ```
4. **明细日志** `/data/verify.jsonl`：每首一行完整报告，便于事后统计误报率：
   ```json
   {"at":"2026-10-26 19:40:12","sid":108581,"title":"Baby Baby","artist":"林俊杰",
    "source":"网易云官方","level":"lossless","third_party":false,"file":"/data/tmp/Baby Baby.flac",
    "state":"passed","passed":true,"summary":"一致性校验通过（5/5 项）",
    "items":[{"key":"duration","label":"时长","state":"pass","local":221.0,"ref":221.0,"score":1.0},
             {"key":"bgm","label":"音乐 bgm","state":"pass","score":0.9910}, ...],
    "reference":{"audio_ref":true,"audio_ref_level":"standard",...},"elapsed_ms":3412}
   ```
5. **接口** `GET /api/verify/report?track_id=<id>`：返回该曲目的 `verify_state` + 完整明细。
6. **命令行**（容器内，不依赖 Web 界面）：
   ```bash
   # 单曲
   python /app/tests/verify_check.py --file /music/musics/x.flac --sid 108581
   # 批量复核曲库（统计误杀率；--verbose 看失败明细）
   python /app/tests/verify_check.py --library --limit 50
   # 离线自测（合成音频，不联网）
   python /app/tests/verify_check.py --self-test
   ```

## 七、配置（`config.json` → `verify`）

```jsonc
"verify": {
  "enabled": true,                                  // 总开关
  "items": ["duration","artist","album","bgm","voiceprint"],
  "duration_tolerance": 2.0,                        // 秒
  "album_threshold": 0.82,
  "bgm_threshold": 0.80,
  "voiceprint_threshold": 0.62,
  "pitch_tolerance": 0.06,                          // 基频中位数相对差
  "on_missing_reference": "skip",                   // 拿不到官方流：skip 不算失败 / fail 算失败
  "only_third_party": false,                        // true=只校验第三方音源下载的曲目
  "keep_failed": false                              // true=失败样本留 /data/verify_failed/
}
```

老配置里没有 `verify` 段时会自动补默认值（`app/config.py` 的 `load()`）。

## 八、已知局限（如实说明）

1. **「声纹」是轻量声学近似**：MFCC 倒谱（反映声道/音色）+ 基频轨迹（反映音高），
   **不是深度学习声纹模型**。它擅长区分「同一个人不同版本」（Live/伴奏）和
   「不同歌手」，但对**同一歌手的不同歌**、或**经过大幅变调/变速**的版本，
   判断力有限。不上模型是刻意的（镜像体积 + 每首数秒推理）；
   要更强的区分力，可以把 `_compare_audio` 里的 MFCC 换成说话人 embedding。
2. **纯音乐 / 器乐**：有效人声帧太少时声纹项自动 `skip`，只剩 bgm + 元数据在把关。
   纯音乐 vs 纯音乐的不同版本（如钢琴版 vs 弦乐版）主要看 bgm。
3. **原曲 vs 高质量伴奏**：bgm 可能到 0.86（编曲相同），靠声纹兜。若两侧都没人声，就会漏。
4. **拿不到官方播放流的歌**（下架/无版权）：音频项 `skip`，只有时长/演唱者/专辑在把关。
   想把这类也判失败，设 `on_missing_reference: "fail"`——但下架歌会永远下载不了。
5. **同名不同版本但元数据一致**（比如官方就是同一个 dt/al/ar 的两个母带）：
   只能靠 bgm/声纹，阈值有极限。
6. 性能：每首增加约 **3~4 秒**（一次取流 + 两侧 ffmpeg 解码 + 特征计算）。
   批量下载上千首时，这会是分钟级到小时级的额外耗时；嫌慢可以开 `only_third_party`
   或调小 `items`。
7. 校验失败**不会自动换音源重试**（本次范围）。要重试请在曲目行改音源偏好后手动再下。

## 九、独立测试怎么做

```bash
# 1) 离线自测：文本规则 + 合成音频（不联网、不需要曲库）
docker exec -w /app music-sync python /app/tests/verify_check.py --self-test

# 2) 单曲实测（需要网易云登录态；--json 出机器可读结果）
docker exec -w /app music-sync python /app/tests/verify_check.py --file /tmp/x.flac --sid 108581

# 3) 阈值复现（正负样本分数分布）
docker exec -w /app music-sync python /app/tests/verify_calibrate.py --root /music/musics --sample 12

# 4) 误杀率复核（拿曲库里已正常播放的歌跑一遍）
docker exec -w /app music-sync python /app/tests/verify_check.py --library --limit 50 --verbose
```
