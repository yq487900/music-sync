# 回收站

菜单位置：**整理** 和 **云盘** 中间。

「整理」里删掉的歌不是真删，是移到 `/data/_trash/<时间戳>/<原来的相对路径>`（歌词 / NFO 一起走），
所以那一刻起：歌单页、下载页、云盘「待上传」里的「本地状态」都会同步变成**未下载**
（`Track.status` 回到 `new`，`file_path` 保留着，方便恢复时对回原曲目）。

## 能做什么

| 操作 | 说明 |
|---|---|
| **恢复** | 放回音乐库原来的位置（同名文件已存在时加「(回收站恢复)」后缀，不覆盖）；曲目记录同步变回「已下载」 |
| **清空** | **真正删除本地文件**（会弹确认框）；曲目记录的文件路径也一起清掉 |
| 单首 / 勾选批量 / 全部 | 每行前面有勾选框；上方「勾选本页 / 取消本页 / 全部勾选 / 全部取消」，再配合「恢复勾选的 / 清空勾选的 / 全部恢复 / 全部清空」 |
| 搜索 | 按歌名 / 歌手 / 专辑 / 文件名搜，便于单独处理某一首 |

页面顶部有统计：回收站曲目数、占用空间、删除批次数。

## 实现位置

- 后端：`app/organize.py` 的 `to_trash` / `trash_items` / `from_trash` / `purge_trash`
- 接口：`/api/trash`（列表）、`/api/trash/restore`、`/api/trash/purge`；
  删除接口 `/api/organize/delete` 会顺手同步曲目状态
- 前端：`app/templates/trash.html`
- 自测：`bash tests/organize_test.sh`（第 8–12 步覆盖 删除 → 列表 → 恢复 → 彻底清空；
  **只清理测试自己造的文件，不动回收站里别的东西**）

## 注意

- 「清空」不可恢复（真实 unlink），所以有确认框
- 回收站列表不读封面（那样要额外读标签，列表会变慢），统一用音符占位图标
