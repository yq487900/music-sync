# 云盘备份

把本地下载好的歌曲上传到**网易云音乐云盘**，并让网易云补齐歌曲信息。

## 功能

| 能力 | 说明 |
|---|---|
| 云盘歌曲列表 | 读取账号云盘歌曲（默认 20 首/页，可翻页），带封面、时长、文件大小 |
| 配额显示 | 云盘歌曲数、已用容量 / 上限、本地已下载数、待上传数 |
| 单个上传 | 「待上传的本地歌曲」列表里逐首点「上传」 |
| 批量上传 | 「全部上传」把本地已下载但未上传的一次性入队 |
| 自动上传 | 配置页开启「下载完成后自动上传云盘」后，每首下好即刻排队上传 |
| 上传队列 | 实时进度（字节/百分比），可暂停 / 继续 / 取消 |
| 删除 | 云盘列表里点「删除」可移除云盘歌曲（同时清掉本地记录） |
| **搜索** | 云盘歌曲卡片顶部搜索框可搜**整个云盘**（不只是当前页），支持「歌手 歌名」多词 |
| **编辑纠错** | 每首歌右侧「编辑」→ 输入正确的网易云歌曲 ID 点「匹配」，纠正网易云的乱匹配 |
| **元数据补齐** | 上传成功后向网易云请求曲库匹配，把封面 / 专辑 / 歌手 / 歌词写回本地文件与标签 |

## 云盘歌曲纠错（按 ID 匹配）

网易云会给上传的文件自动匹配曲库条目，匹配错了（歌手/专辑/封面/歌词都不对）时用这个纠正：

1. 云盘歌曲列表里点这首歌右侧的「编辑」
2. 两种找歌方式（可以只用其中一种）：
   - **按关键词搜**：填「歌手 歌名」，从候选列表里点正确的那首（会自动把 ID 填进右边输入框）
   - **按网易云歌曲 ID**：直接填 ID（如 `5257138`）
3. 点「匹配」→ 网易云把这首歌重新绑定到你指定的正式曲目

匹配后这首歌就改用正式曲目的标签 / 封面 / 歌词；如果这个文件是本工具上传的，还会**顺手把新元数据回填到本地文件与标签**。

> 说明：网易云的云盘歌曲不允许直接改标题/歌手文本，只能通过「匹配到正式曲目」来换元数据。
> 所以这里用匹配实现纠错，而不是逐字段手填。

## 上传后自动校准（以歌单数据为准）

配置页「上传后自动校准」开关默认**开**。每首歌上传成功后自动做两件事：

1. **让云盘条目匹配到正式曲目** —— 网易云不保存上传文件里的封面，云盘条目只有匹配上才有封面
2. **按歌单里的数据校准本地文件** —— 以**这首歌在他歌单里那条**（`platform_track_id`）的
   网易云官方信息为准，逐项核对并纠正本地的**歌名 / 歌手 / 专辑 / 封面 / 歌词**，
   同时刷新 NFO 和整理页缓存

判定与保护规则：

- 只有**确实不一致**才动文件；每次都把改动写进日志与 `/data/calibrate.jsonl`
  （形如 `歌名：X → Y；封面：本地那张和歌单的不是同一张 → 换成歌单封面（2 KB → 40 KB）`）
- **网易云没有的字段绝不写空**（沿用本地现值）；网易云没有歌词时保留本地歌词
- **占位图（< 8 KB 灰底红音符）一律不当封面**；太小 / 不是图片的图直接丢
- 网易云没有这首歌的正式条目（`al.id = 0`，例如某些云盘条目自己的 id）→ 整体跳过
- 做完了再跑一次结果一致（幂等），不会反复重写文件

> 想让它别管：配置页把「上传后自动校准」关掉即可，不用改代码。
> 注意 2026-09 实测的两条硬规则（详见 `云盘封面问题排查.md`）：网易云不保存上传文件里的封面，
> 接口也没有设置云盘封面的入口；云盘条目的封面只能靠「匹配到正式曲目」。

> 自压或翻唱文件通常匹配不到曲库条目，此时只保留上传时写入的信息，不会出错。

## 云盘条目的封面为什么是「无封面」

云盘列表里某条带「云盘无封面」小标时，说明这条既没匹配到正式曲目（`al.id = 0`），
网易云自己也没存封面 —— 它显示的是那张灰底红音符占位图。**这没法从接口侧修改**：

- 上传接口只提交 歌名 / 专辑 / 歌手（读文件标签），没有封面字段
- 实测把带醒目封面的文件传上去，条目依然 `coverId = 0`

想少看到这种条目，可以在云盘列表里删掉它（重传只会再多一条）。

## 歌单 / 下载页的状态图标（💾 + ☁）

歌单详情页、下载页每首歌**最右边两个图标**：左边一个**软盘**看本地，右边一朵**云**看云盘。

| 图标 | 含义 |
|---|---|
| 💾 白色软盘 | 已在本地（下载好了） |
| 💾 白色软盘 + 红色感叹号 | 本地没有（未下载；若是下载失败，悬停能看到失败原因） |
| ☁ 白色小云朵 | 在云盘 |
| ☁ 白色小云朵 + 绿色勾 | 在云盘，**而且本地也有** |
| ☁ 红色小云朵 + 白色感叹号 | 不在云盘 |
| ☁ 灰色小云朵 | 云盘数据还在后台读（未知，不谎报「不在」） |

图标 30px，固定在操作区最后两列（各 30px 宽），所以每一行的两个图标都排成一竖线。
鼠标停在云朵上能看到判断依据的数据时间（如「依据 20:41 的云盘数据」）。

（图标是内联 SVG，符号在 `base.html`（`ic-disk` / `ic-disk-alert` / `ic-cloud` / `ic-cloud-check` /
`ic-cloud-alert`）；`<use>` 引出来的内容没法用外部 CSS 上色，所以每个状态的颜色写死在符号里。）

## 云盘页（云盘歌曲列表）

每行最右边**三个图标**（都是 45px，排成一竖线）：

| 图标 | 含义 |
|---|---|
| 💾 / 💾+红感叹号 | 这首歌在不在**本地** |
| ☁ / ☁+绿勾 / 红云+白感叹号 | 在不在**云盘**（云盘页里必然「在」，有绿勾=本地也有） |
| 列表图标（白 / 红+白感叹号 / 灰） | 在不在**我的歌单**里；灰=认不出是哪首（云盘条目没匹配到正式曲目） |

**无封面的歌**（网易云数据库里没有这一首，例如周杰伦的一些歌）：封面位置显示 🚫，
鼠标移上去会提示「请在手机 App 或电脑客户端重新上传一次」。

云盘歌曲的筛选片：**封面/信息**（有/缺）、**在本地**（在/不在）、**在歌单**（在/不在）——
组间是「并且」。注意「有封面」和「有专辑信息」在网易云里是**同一个条件**（都得先匹配到正式曲目），
所以合成了一档，没有拆成两个重复的。

云盘页的列表、搜索、筛选、数字**全部走云盘索引**（不逐页拉接口），所以是秒回；
打开页面时会强制重新索引一遍（带 15 秒防抖），跑完页面自动刷新。

索引刷新速度：云盘列表接口**一次能拉 1000 条**，所以整表刷新只要 4 个请求、**约 8 秒**
（原来按 100 条/页 = 40 个请求、20 秒以上）。歌单索引只重拉变过的歌单，通常 1 秒内完成。

## 把云盘里的歌加进歌单

云盘歌曲列表每行最后那个「**是否在歌单里**」图标：

| 图标 | 含义 | 能点吗 |
|---|---|---|
| 白色列表（带音符） | 在你的某个歌单里 | — |
| **红色列表 + 白感叹号** | 不在你的任何歌单里 | **可以点** → 弹出歌单选择框，勾一个或多个歌单 → 「加入选中的歌单」 |
| 灰色列表 | 认不出是哪首（云盘条目没匹配到正式曲目） | 不能加（没有歌曲 ID） |

加入成功后会自动重拉歌单索引，图标跟着变白。接口：`POST /api/playlists/add-tracks`。

- **只有匹配到正式曲目的条目能加**（未匹配的条目没有真正的歌曲 id，点了会提示先去客户端重传）
- ⚠️ 这个自建 ncm-api（`@neteasecloudmusicapienhanced`）里加歌必须走 **`/playlist/tracks`**
  （`op=add|del` + `pid` + `tracks=逗号分隔id`）。踩过的坑：
  `/playlist/manipulate/tracks` 这个路由**根本不存在**（返回空 body）；
  `/playlist/track/add` 存在但用的是网易云**已废弃**的旧上游接口（恒回 `401 无权限操作歌单`）

## 云盘纠错的三种提示是什么意思（实测 2026-09）

用「编辑 → 按网易云歌曲 ID 匹配」纠正云盘条目时，网易云可能回三种话，界面上都翻译成人话了：

| 网易云原话 | 真实含义 | 怎么办 |
|---|---|---|
| **不支持匹配** | 网易云没认出这条音频（所以它在云盘里一直是「未匹配」）。这类条目一律不允许绑定正式曲目 | 改不了。删掉云盘里那条 → 用手机 App / 电脑客户端重新上传一次（客户端会做音频指纹识别） |
| **（匹配成功后重复点）文件不存在** | 匹配**已经成功**了：网易云把旧的「未匹配」记录合并/换成了一条新记录（新 id + 补上封面） | 刷新页面，新的那条才是最新的，不用再匹配 |
| **纠错后的文件已在云盘存在** | 你想绑过去的那个 id **已经在你的云盘里了**（要么是同一首歌已有正式版条目，要么你点到的是「你自己那条未匹配的云盘记录」——网易云搜索会把用户自己的云盘记录混进搜索结果里） | 这条只是少个封面，不影响听；想干净点就在云盘页把它删掉，或用手机 App / 客户端重传 |

> **防呆**：编辑面板的搜索结果里，凡是 id 已经在你云盘里的，都会带一个红标「已在你的云盘」，
> 点了也会直接告诉你原因，不会让你白试一遍。

> 提示里会直接列出重复的那条（例：`《达尔文》林俊杰 · JJ的咖啡调调, Vol. 2（已匹配、有封面）`）。

## 单个歌单的「扫描补齐」

歌单详情页工具条上（「加入同步」右边）有 **扫描补齐这个歌单**：

1. 先只**预演**：告诉你这个歌单共几首、云盘里有几首、需要下载几首、需要补传几首（列出歌名）
2. 你确认后才真排队：本地没有的 → 下载；本地有但云盘没有的 → 补传云盘（下载完是否自动上传看开关）
3. 每轮上限跟「歌单监控每轮最多处理」一样（默认 20 首），剩下的再点一次继续

接口：`POST /api/playlists/{pid}/fill`，`{"dry": true}` 只算计划。

## 筛选

歌单详情页和下载页顶部都有一排**筛选片**，点一下只看那一类；两组之间是「并且」
（比如「未下载」+「不在云盘」= 要从头下载再上传的歌）。片子上的数字是当前数量。

| 页面 | 筛选 |
|---|---|
| 歌单详情页 | 本地：全部 / 已下载 / 未下载　·　云盘：全部 / 在云盘 / 不在云盘 |
| 下载页 | 曲目：全部 / 未下载 / 已下载 / 失败 / 已勾选　·　云盘：全部 / 在云盘 / 不在云盘 |
| 整理页 | 标签：全部 / 有 / 缺　·　封面：全部 / 有 / 缺　·　歌词：全部 / 有 / 缺 |

筛选在**服务端**做（先筛再分页），所以页码和总数都对得上（接口参数：
`local=all|yes|no`、`cloud=all|in|out`、`tag/cover/lyric=all|yes|no`）。

判定依据（从精确到宽松，命中任一即算「在云盘」）：

1. **歌曲 ID 精确比对** —— 云盘条目被网易云匹配到正式曲目时，条目的 id 就是网易云的歌曲 ID，直接对得上
2. **本地上传记录** —— 本工具传上去的歌，本地库记着当时拿到的云盘 id
3. **歌名 + 歌手比对** —— 自己上传、网易云没认出来的歌，云盘条目用的是**文件里的标签**，
   所以按「歌名（去掉 feat./括号后）+ 第一个歌手」比；歌名较长（≥5 字）时允许只比歌名

**不会误报**：索引还没建立时显示「云盘未知」而不是「不在云盘」；歌名太短（如「精卫」）且歌手对不上时不猜。

## 云盘索引（为什么它不慢）

云盘列表接口只能一页页翻（3900 首 ≈ 40 次请求、约 30 秒）。所以歌单页**不现拉**：

- 后台任务 `cloud_index` 在服务启动时拉一次全量，之后**每 10 分钟**刷新（见 `app/scheduler.py`）
- 结果存成索引：内存 + `/data/cloud_index.json`（容器重建也不丢，重启后从磁盘直接读回）
- 歌单页只读内存索引，秒回；索引缺失或过期时后台补一次，页面照常显示，不等待
- **打开歌单时强制重新索引一遍**（`ensure_async(force=True)`，带 15 秒防抖）：
  打开歌单页 → 后台重拉一遍云盘 → 拉完页面自动再刷一次。所以「刚看过的歌单」状态是最新的
- **限流防御**：网易云偶尔返回被截断的列表（实测 3931 条只回 2600 条）。拿到明显变小的
  结果时**保留原索引**并记一条日志，否则明明在云盘的歌会被误报成「不在云盘」
- **本工具上传成功的歌会立刻登记进索引**（`CloudIndex.note_upload`）——
  否则要等下一次整表刷新（最多 10 分钟）才认得它，这段时间页面会把这歌误报成「不在云盘」，
  看着像上传失败。（2026-09-22 手动下载《꽃(FLOWER)》时实际踩到过这个窗口）

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/cloud` | 云盘歌曲列表（`page` / `size`） |
| GET | `/api/cloud/quota` | 配额与统计 |
| GET | `/api/cloud/local` | 本地待上传列表（`page` / `size`） |
| POST | `/api/cloud/upload` | `{ids:[…]}` 指定曲目；`{all:true}` 全部待上传 |
| POST | `/api/cloud/upload/{tid}` | 单曲上传 |
| — | 上传成功后自动校准 | 见上节；结果追加在 `/data/calibrate.jsonl` |
| DELETE | `/api/cloud/{sid}` | 删除云盘歌曲 |

## 实现要点

- 上传走自建 `ncm-api` 的 `/cloud` 接口（内部完成：MD5 校验 → 申请上传凭证 → 上传到网易云 NOS → 登记云盘信息）
- **成功码是 200 或 201**（网易云对已存在内容返回 200，新内容返回 201）
- 云盘歌曲 id 在响应的 `privateCloud.simpleSong.id`；顶层 `songId` 是内容哈希，不能当歌曲 id 用
- 上传耗时与文件大小成正比（几十 MB 的无损会明显偏慢），因此走队列并显示实时进度
- 上传并发固定为 1，避免同时挤占带宽影响下载

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| `上传文件的音频解析失败，请确认当前文件是否为音频`（服务端 409） | 网易云侧间歇性故障，与文件本身无关（实测同样文件再传即可过）。程序会自动重传 2 次；仍失败就稍后再传 |
| 点「匹配」提示「网易云没认出这首歌的音频」 | 这条云盘记录没被网易云匹配到正式曲目，网易云拒绝绑定，非程序问题（见上一节） |
| 云盘条目没有封面（列表带「云盘无封面」小标） | 网易云不保存上传文件里的封面，接口也没有设置入口；不想看到就删掉这条 |
| `还没登录网易云，无法上传` | 到配置页顶部重新扫码登录 |
| 一直停在「上传中」 | 无损大文件较慢，可看进度百分比；卡死可取消后重试 |
| 云盘里出现重复条目 | 网易云按内容去重，同一首歌不同标签版本可能并存，可手动删除 |
