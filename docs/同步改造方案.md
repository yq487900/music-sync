## 一、为什么要改

当前项目里的同步/下载代码基本是空壳，而且和登录是同一个毛病——**直连网易云网页接口**：

| 文件 | 现状 | 问题 |
|---|---|---|
| `app/sync/netease.py` | 直连 `/api/user/playlist`、`/api/playlist/track` | 网页未加密通道，取不到数据 |
| `app/sources/luoshe.py` | 指向第三方代理站 `music.52pojie.cn` | 不受控，站点随时可能失效 |
| `app/download_worker.py` | 19 行骨架 | 没有实际下载逻辑 |
| `app/metadata/scraper.py` | 14 行骨架 | 没有刮削逻辑 |

**已完成的登录改造**已经引入了 `ncm-api` 容器（`app/ncm.py` 里封装好了客户端），同步正好可以复用它，不用再引入新东西。

## 二、参考项目的做法（照搬这套流程）

所有请求经 `ncm-api`，不再直连网易云：

1. `/user/account` → 拿到 `userId`
2. `/user/playlist` → 列出账号下**全部歌单**（含「我喜欢的音乐」），自动翻页
3. `/playlist/detail` → 取 `trackIds`（**完整列表**；`/playlist/track/all` 上千首会被截断到 499）
4. `/song/detail` → 每 100 首批量补齐标题、歌手、专辑、时长、**音质权限**
5. `/song/url/v1?id=&level=` → 按音质链**逐档降级**取直链，跳过只有试听片段的（`freeTrialInfo`）
6. 直链下载 → 临时目录 → **校验 MD5/文件大小** → 写标签 → 移入音乐库
7. 附带产物：歌词（`/lyric`）、封面、NFO（Emby/Jellyfin/Kodi 能识别专辑/歌手）
8. 工程细节：请求限速（默认 0.35 秒/次，防风控）、失败退避（连续失败 3 次则 24 小时内不再重试）、403/410 视为直链过期自动重取一次

## 四、默认参数（都放进配置页，不满意随时改）

- **目录结构**：按专辑分类（`歌手/专辑/01. 歌名.mp3`），另有「按歌手 / 按歌单 / 全部平铺」可选
- **音质链**：`jymaster > hires > lossless > exhigh > standard`（有会员就自动拿最好，没有就降档）
- **请求间隔**：0.35 秒
- **下载并发**：3
- **失败退避**：连续失败 3 次，24 小时内不再重试
- **是否保留洛舍兜底**：默认**关闭**（网易云自己拿不到音源的曲目记为「失败」，在下载页能看到原因）
