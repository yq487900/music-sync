# 歌单监控

配置页「歌单监控」开关（默认**关**）。打开后，后台每 10 分钟检查一次：
**我的网易云歌单里有没有新歌**、**云盘里缺不缺歌**，按需要自动排队下载 / 补传云盘。

## 两种监控方式

| 方式 | 干什么 |
|---|---|
| **从现在开始监控**（默认） | 只处理「打开监控**之后**才加进歌单」的歌（用网易云给的加入时间 `at` 判断） |
| **全量扫描歌单：补齐不在云盘的** | 先把我**所有歌单**里的歌跟云盘对一遍：云盘没有的 → 本地已有就排队补传云盘，本地没有就排队下载；补完之后**自动转成「从现在开始监控」** |

每轮最多处理几首，由「高级设置 → 歌单监控每轮最多处理」决定（默认 20 首，分批慢慢做）。
下载完成后要不要顺手上传云盘，看**「下载完成后自动上传云盘」**那个开关。

## 在不在云盘怎么判断

查云盘索引（`app/cloud_index.py`）：

- 能匹配到正式曲目的云盘条目 → 用歌曲 id 精确比对
- 自己上传、网易云没认出来的条目 → 用「歌名（去掉 feat./括号）+ 第一个歌手」比对
- 本工具上传成功的歌：上传那一刻就立刻登记进索引（不用等下一轮刷新）
- 索引还没建好 → 不算「没有」（避免误报）

## 歌单索引（在不在歌单 / 新歌判定）

`app/playlist_index.py`：

- 拉 `/user/playlist` 拿到我所有歌单，每个歌单带 `trackCount` / `updateTime`
- **只重拉变过的歌单**（没变过的直接用缓存）→ 稳态下一轮只有 1 次请求
- 存 `/data/playlist_index.json`（带 `version`，格式变了自动失效重拉）
- `at` 是加入歌单的时间：网易云给的是**毫秒**，统一换成秒再存
  （不换的话「从现在开始监控」会把几千首老歌当成新歌下一遍）
- `at` 缺失（=0）的老歌不会被「从现在开始」选中

## 先看它打算做什么（预演）

不想直接开开关又不知道它会干嘛，可以先跑预演（只算计划，不下载、不改配置）：

```bash
docker cp ms_monitor_dry.py music-sync:/tmp/ && docker exec music-sync python /tmp/ms_monitor_dry.py
```

（脚本在工作区 `ms_monitor_dry.py`，配套 `rootrun.sh root_ms_dry.sh` 直接跑。）

## 现实提醒（2026-09-22 实测）

| 数字 | 值 |
|---|---|
| 我的歌单里的歌 | **7838 首**（66 个歌单） |
| 其中在云盘的 | **2049 首** |
| 云盘里的歌 | 3931 首（其中在歌单里的 2049 首） |
| → 歌单里「云盘没有」的 | 约 **5600+ 首** |

所以「全量扫描补齐」在现在是**大动作**（下载约 5600 首 + 上传云盘可能超容量），
开之前先看清预演数字，或者先只监控（不改历史）。
